# Document Upload + Encryption Pipeline for the FastAPI Backend

## Context
The FastAPI backend (`Backend/`) already has Auth0 cookie auth, a pooled async Postgres engine, and a `users` table. `protect.ipynb` contains the envelope-encryption flow (AES-256-GCM document encryption, RSA-OAEP KMS-wrapped DEK, KMS-signed manifest, SSE-KMS S3 upload of 3 objects) that must run on every uploaded document. This task adds a concurrent per-document upload API with per-document SSE status streams (`UPLOADED → ENCRYPTING → PREPARING → READY`), a `documents` table (FK-cascade to `users`), one shared aioboto3 session/client started at server startup, and hash-based dedup — all while keeping the notebook's function code as close to verbatim as possible (only converted to async).

**Already satisfied (no change):** DB pooling — `app/database.py` already creates one module-level `create_async_engine` (pool_pre_ping, recycle=300) at startup; requests reuse it via `Depends(get_db)`. Note: user-id for the S3 path = `str(user.id)` (UUID) which passes the notebook's `^[A-Za-z0-9_-]{1,128}$` pattern.

## New requirements folded in (from user's answers)
- Auth is MANDATORY before any byte is accepted (FastAPI solves `get_current_user` before parsing the multipart body).
- Store `file_sha256` per document; check duplicates for that user before accepting.
- Max size 10 MB; only `application/pdf`, `image/png`, `image/jpeg`.
- Duplicate original filenames get suffixed `name(1).ext`, `name(2).ext`….
- Stored file renamed to `{document_id}.{ext}` (pdf/png/jpg — slashes can't appear in filenames).
- Final SSE status: `READY`.

### 6. `Backend/app/jobs.py` (new) — in-memory per-document SSE job registry
- `DocumentJob(document_id, user_id)`: ordered `events` list (buffered for replay), subscriber `asyncio.Queue`s, `done` flag. `emit(status, data)` appends + fans out.
- Global registry `dict[document_id → DocumentJob]` guarded by an `asyncio.Lock`; entries removed ~30 min after terminal event (TTL task). Also holds the **in-flight original-filename set per user** used for duplicate-name suffixing (see upload flow), since SSE may connect after `UPLOADED` was emitted.
- `run_document_pipeline(job, …)`: emits `ENCRYPTING` → `await prepare_document(...)` → emits `PREPARING` → `await upload_document(...)` → delete `{document_id}.ciphertext` from `encrypted/` (encrypted temp only; original kept forever) → insert `Document` row (own `SessionLocal` session, commit) → emit `READY` with the stored record. On exception: emit `ERROR` (message), best-effort delete ciphertext temp, log. Fired via `asyncio.create_task` with a kept strong reference.

### 7. `Backend/app/routers/documents.py` (new) — prefix `/api/documents`, all endpoints `Depends(get_current_user)`
- **`POST /api/documents/upload`** (multipart `file: UploadFile`) → 201 `{document_id, original_filename, size, mime_type, sha256}`:
  1. Auth dependency already resolved (before multipart body parse).
  2. Reject early: content_type/extension not in allowed set (415); `Content-Length` > 10 MB (413).
  3. Stream to `uploads/originals/{uuid4().hex}.part` in 1 MB chunks via aiofiles, incrementally computing SHA-256, counting bytes (413 if over cap mid-stream), and sniffing magic bytes of the first chunk (`%PDF`, `\x89PNG`, `\xFF\xD8\xFF`) for defense in depth.
  4. Duplicate check `SELECT … WHERE user_id=:u AND file_sha256=:h` → if found: delete `.part`, return **409** with the existing `document_id` (no job, no SSE).
  5. `document_id = generate_document_id()`; pick display `original_filename` under the registry lock: base name, then `name(1).ext`, `name(2).ext`… skipping names in the in-flight set or already in the DB.
  6. Rename `.part` → `originals/{document_id}.{ext}` (`await aiofiles.os.rename`).
  7. Create job, emit `UPLOADED`, spawn pipeline task, return 201.
- **`POST /api/documents/duplicates`** body `{sha256}` → `{exists, document_id?}` — lets the frontend skip the upload entirely (client-side SubtleCrypto hash) before any byte is sent; server-side step 4 stays authoritative.
- **`GET /api/documents/{document_id}/events`** → SSE (`EventSourceResponse`, `text/event-stream`): 404/403 if the job's user isn't the caller; replays buffered events (`UPLOADED`…), then streams live until `READY`/`ERROR`, then closes. Format: `event: <STATUS>` / `data: {"document_id":…, "status":…, …}`. Cookie auth works with `EventSource` (cookie path is `/api`).

## Frontend contract (documentation only — no frontend changes in this task)
Per dropped file: optional `POST /api/documents/duplicates` → XHR/fetch upload with `credentials: "include"` (progress from XHR `upload.onprogress`, client-side only) → on 201 open one `EventSource` per `document_id` and render `UPLOADED → ENCRYPTING → PREPARING → READY/ERROR`. Concurrent drops = concurrent POSTs; the server never queues them.

## Notes / limitations
- Single uvicorn worker assumed (in-memory job registry + filename lock). Multi-worker would need Redis pub/sub — out of scope.
- Server restart loses in-flight SSE jobs (originals remain on disk); DB truth is unaffected.
